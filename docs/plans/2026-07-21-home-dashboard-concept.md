# 홈(Today 실행 대시보드) 기획 v1 — 2026-07-21

운영자 리뷰 지적: "홈에 관한 기획은 여전히 부실". 증상은 시작 화면을
`일정`으로 두면 홈이 리다이렉트 카드 1장 + 하드코딩 검색 질의 1개("회의 마감
후속 조치 일정")에 의존한 얇은 화면이 되고, 검색이 실패하면 원시 오류
배너("일정 후보를 불러오지 못했습니다")만 남는다는 것.

## 홈의 정의

홈은 **오늘 실행 대시보드**다. 메일에서 파생된 오늘의 실행 컨텍스트 —
답장 SLA, 실행 항목(작업), 일정 원본 연결 상태, 메일 기반 일정 후보 — 를
**서명 세션 API 실데이터로만** 구성한다. 고정 문구 카드·가짜 수치·원시 오류
배너는 홈에 존재하지 않는다.

## 시작 화면 선택의 역할 재정의

`시작 화면(홈/메일/일정)`은 **어떤 배치로 시작하느냐**의 선호일 뿐,
홈 콘텐츠의 품질 계층이 아니다. 세 배치 모두 동일한 실데이터 소스를 쓴다:

- `홈`: 종합 배치 (지표 4 + 답장 대기 + 최근 메일 + 작업 + 빠른 실행).
- `메일`: 메일 작업공간(3-pane)을 즉시 연다 (현행 유지).
- `일정`: **일정 중심 배치** — 이번 리뷰로 재구현. 아래 참조.

## 일정 시작 화면 v1 (이번 구현)

정보 위계 (위 → 아래):

1. **오늘 헤더**: 오늘 날짜 + `일정 관리 열기`(주 CTA, `/calendar`) +
   `메일 작업공간 열기`(보조).
2. **일정 실행 지표 3개** (실데이터): 일정 원본 n(반영 가능 n) · 답장 대기 n ·
   대기 작업 n.
3. **일정 원본 연결 상태**: `/api/calendar/writeback-sources` 행별로 프로토콜
   라벨·기능(읽기/일정 반영/충돌 검사)·충돌 토큰 상태. 원본이 없으면 설정
   화면으로 안내하는 빈 상태. 원본 이벤트 목록은 서버 이벤트 API가 없으므로
   **"원본 연동 후 표시"로 정직하게 라벨** (v2 참조).
4. **메일 기반 일정 후보**: `/api/search` 결과. 로딩/빈/오류 3상태를 동일한
   톤으로 보여주고 오류에는 재시도 버튼을 단다. 원시 destructive 배너 금지.
5. **오늘의 실행 항목**: `/api/tasks` 중 미완료 상위 3건 + 작업 보드 링크.
6. **답장 대기**: `/api/emails/pending-replies` 상위 3건 + 메일함 링크.

## 데이터 소스 매핑 (전부 서명 세션 API)

| 위젯 | 소스 | 상태 |
|---|---|---|
| 답장 대기 | `/api/emails/pending-replies` | 사용 중 |
| 실행 항목 | `/api/tasks` | 사용 중 |
| 일정 원본 상태 | `/api/calendar/writeback-sources` | 사용 중 |
| 일정 후보 | `/api/search` (컨텐츠 검색) | 사용 중 · 질의 고도화 예정 |
| 오늘 일정 이벤트 | 없음 — 서버 이벤트 조회 API 부재 | **v2 신규 API 필요** |

## 오류·빈 상태 원칙 (홈 전역)

- 로딩/빈/오류는 같은 시각 톤(카드형)으로, 오류에만 재시도 액션을 단다.
- deny-first 403(admin 전용 표면)은 "권한 필요"로 구분해 표기한다 —
  "불러오지 못했습니다"와 섞지 않는다 (백로그 문서 B-12 항목과 연동).

## 로드맵

- **v1 (이번 구현)**: 일정 시작 화면 실데이터화 + 오류 상태 정돈.
- **v2**: 서버 일정 이벤트 조회 API(오늘/이번 주, opaque source 스코프) →
  홈 오늘 타임라인. 판단 포인트 피드 통합. 일정 후보 질의를 사용자 컨텍스트
  (최근 스레드·참석자)로 생성.
- **v3**: 오늘 브리핑(LLM 요약, provider 라벨과 근거 링크 포함) — AI Hub
  프롬프트 감사 경로를 재사용.
